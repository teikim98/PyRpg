칸 `(r, c)`에서 도착까지 가는 길의 수를 `paths(r, c)`라고 하면, 오른쪽으로 한 칸 간 뒤의 길과 아래로 한 칸 간 뒤의 길을 더하면 돼: `paths(r, c) = paths(r, c + 1) + paths(r + 1, c)`.

- **기저 조건** 두 가지: 격자 밖이거나 바위면 `0`, 도착 칸이면 `1`. 순서가 중요해! 바위 검사를 **먼저** 해야 도착 칸이 바위일 때 `0`이 나와. 도착 검사를 먼저 하면 바위인 도착 칸에서도 `1`을 돌려줘.
- 격자 밖 검사(`r >= R or c >= C`)도 `grid[r][c]`를 읽기 **전에** 해야 해. 아니면 오른쪽 끝을 넘어서 `IndexError`가 나. `or`는 앞이 참이면 뒤를 보지 않으니까 `r >= R or c >= C or grid[r][c] == "#"` 한 줄로 안전하게 쓸 수 있어.
- **메모 없이** 재귀하면 같은 칸을 수없이 다시 계산해. 60×60 빈 격자는 길이 10^34가지가 넘어서, 길을 하나씩 세는 재귀는 영영 안 끝나. `memo[(r, c)]`에 칸마다 답을 적어 두면 칸 3,600개를 한 번씩만 계산해. dict 키로 튜플 `(r, c)`를 쓸 수 있다는 것도 기억해 둬.
- `@lru_cache(maxsize=None)`를 붙여도 정답이야. 재귀 깊이가 R + C(최대 120) 정도라 안전해.
- 반복문 DP도 정답이야: `dp[r][c] = dp[r - 1][c] + dp[r][c - 1]`(바위면 0)을 왼쪽 위부터 채우면 `dp[R - 1][C - 1]`이 답이야. 메모 재귀와 같은 표를 반대 방향에서 채우는 셈이지.
