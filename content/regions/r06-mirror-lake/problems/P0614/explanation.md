점화식을 그대로 재귀로 짜고, **한 번 구한 세기는 dict에 적어 두면** 돼.

- 기저 조건: `if n == 0: return 1`. 세기 0은 `0 // 2 = 0`이라 기저가 없으면 자기 자신을 끝없이 불러서 `RecursionError`가 나. 기저를 `n == 1`로 두면 바로 이 함정에 빠져.
- 메모: `memo = {}`를 함수 밖에 두고, `if n in memo: return memo[n]`으로 꺼내 쓰고, 처음 구했으면 `memo[n] = echo(n // 2) + echo(n // 3)`로 적은 뒤 돌려줘. 질문마다 새 dict를 써도, 질문 사이에 같은 dict를 함께 써도 돼.
- `from functools import lru_cache`를 쓰고 함수 위에 `@lru_cache(maxsize=None)`(또는 `@cache`)을 붙여도 똑같이 기억해 줘. JS로 치면 함수를 `Map` 메모로 감싸 주는 도우미 함수야.
- 답은 질문마다 한 줄씩. 합만 출력하면 안 돼.

**왜 메모 없는 재귀는 끝나지 않을까?**

- `echo(n)`은 `echo(n // 2)`와 `echo(n // 3)`을 부르고, 둘이 각자 또 `echo(n // 6)`을 불러. 같은 세기를 여러 갈래에서 몇 번이고 처음부터 다시 계산하는 거야. 부르는 횟수는 답 E(n)의 두 배쯤이고, E(10^18)은 약 224조야. 1초에 수백만 번 불러도 몇 년이 걸려.
- 그런데 실제로 거치는 **서로 다른** 세기는 `n // (2^a × 3^b)` 꼴뿐이라 n = 10^18이어도 1000개 남짓이야. 메모가 있으면 이 값들만 한 번씩 계산하고 끝나.
- 크기 n+1짜리 리스트로 0부터 n까지 채우는 풀이는 1페이즈(n ≤ 10,000)에서는 맞지만, n = 10^18이면 리스트를 만들 수가 없어(`MemoryError`, 브라우저에서는 `OverflowError`). 만들 수 있다 쳐도 10^18칸을 채우는 데 끝이 없어. '필요한 값만' 저장하는 dict 메모가 답이야.
- 재귀 깊이는 n을 계속 2로 나누는 길이라 log₂(10^18) ≈ 60단계뿐이야. 브라우저에서도 안전해.
- 이 문제에서는 그냥 `@lru_cache`(최근 128개만 기억)도 통과해. 깊이가 60이라 지금 계산 중인 갈래의 값들이 128개 안에 들어가거든. 하지만 문제마다 다르니 `maxsize=None`을 습관으로 들이자.

**시간 결계의 예산은 이렇게 정했어.**

- 게임은 기기마다 기준 루프(반복 100만 번 + dict 연산 20만 번)를 재서 `ref`로 삼고, 시간 결계 제한을 `budgetUnits × ref × 1.5 + 50 ms`로 정해. 이 보스의 `budgetUnits`는 **10**이야(ref가 44 ms인 기기라면 제한이 약 0.7초).
- 메모가 있으면 질문 100개를 합쳐도 함수 호출이 20만 번 남짓이라 제한보다 한참 빨라. 질문마다 새 dict를 써도, `lru_cache`를 써도 마찬가지야.
- 메모 없는 재귀는 수백조 번(10^18이면 약 450조 번)을 불러야 해서 제한의 세 배는커녕 며칠을 줘도 못 들어와.
- 결론: **같은 값을 다시 계산하는 재귀에는 메모를.** 그리고 값이 아주 클 때는 리스트 대신 dict로 '필요한 값만'.
