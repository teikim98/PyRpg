`n`번째 돌에 내려서기 직전에는 `n - 1`, `n - 2`, `n - 3`번째 돌 중 하나에 있었어. 그래서 `ways(n) = ways(n - 1) + ways(n - 2) + ways(n - 3)`이야.

- **기저 조건**: `ways(0) = 1`(아무것도 안 뛰는 방법 하나), 음수 칸은 갈 수 없으니 `0`. 음수 처리가 없으면 `ways(-1)`, `ways(-2)`, … 로 끝없이 내려가서 `RecursionError`가 나.
- 기저 조건을 피보나치처럼 `if k <= 2: return k`로 쓰면 `ways(0)`이 `0`이 돼서 `ways(3)`부터 틀려(4가 아니라 3). 기저 조건 값은 직접 세어서 확인하자.
- **메모 없이** 재귀하면 `ways(n - 1)` 안에서도, `ways(n - 2)` 안에서도 같은 값을 처음부터 다시 계산해. 호출 수가 한 칸마다 약 1.8배씩 늘어서 `n = 200`이면 우주가 끝날 때까지 안 끝나.
- **dict 메모**: 계산한 값을 `memo[k]`에 적어 두고, 다음에 같은 `k`가 오면 바로 꺼내. 칸마다 한 번씩만 계산하니 200칸이면 200번이면 끝나. JS에서 `Map`으로 메모하던 것과 같아.
- `from functools import lru_cache`를 쓰고 함수 위에 `@lru_cache(maxsize=None)`를 붙여도 같은 메모가 돼. 기본값 `@lru_cache`는 최근 128개만 기억하니까 `maxsize=None`(또는 `@cache`)을 붙이는 습관을 들이자.
- 반복문 DP(`dp[k] = dp[k - 1] + dp[k - 2] + dp[k - 3]`를 작은 `k`부터 채우기)도 정답이야. 메모 재귀와 같은 값을 아래에서부터 채우는 방법이지.
- 이 브라우저에서는 `lru_cache`를 쓴 재귀가 아주 깊으면(수백 단계) 멈출 수 있어서 `n`을 200 이하로 뒀어. 실제 시험 환경은 재귀 한도가 다르니, 깊이가 수천이 넘으면 반복문 DP가 안전해.
