## 1. 디자인 원칙

이 게임의 규칙은 하나입니다: **코딩 실력이 늘어야만 앞으로 나아갈 수 있습니다.** 아래 원칙은 모두 이 규칙을 지키기 위해 정했습니다.

1. **진행을 막는 것은 레벨이 아니라 실력입니다.** 레벨이 아무리 높아도 보스 문제를 풀지 못하면 다음 지역으로 갈 수 없습니다. 레벨은 HP 여유분 같은 완충 역할만 합니다.
2. **실패는 정보입니다.** 틀리면 HP가 깎이지만 작성한 코드는 그대로 남고, 보조 캐릭터가 실패 원인을 설명합니다. 영구적으로 잃는 것은 없습니다.
3. **보상이 학습을 대체하지 않습니다.** 정답 판정을 바꾸거나 테스트를 건너뛰게 해 주는 아이템은 만들지 않습니다.
4. **게임 밖의 실전과 연결합니다.** 함수 구현형(프로그래머스)과 stdin/stdout형(백준)을 모두 연습하고, 지역을 클리어하면 실제 사이트의 문제 번호로 안내합니다.
5. **콘텐츠는 데이터입니다.** 문제, 대사, 맵은 `content/` 아래 데이터 파일로 관리하므로, 문제를 추가할 때 엔진 코드를 고치지 않습니다.

## 2. 세계관과 스토리

### 2.1 세계관

- **세르펜티아 대륙**: 모든 것이 '서펜트 룬'이라는 주문 언어로 움직이는 세계입니다. 서펜트 룬은 게임 속 설정일 뿐이고, 실제로는 Python입니다. 강물이 흐르는 것도, 등불이 켜지는 것도 누군가 써 둔 룬이 실행되고 있기 때문입니다.
- **대정지(The Great Halt)**: 어느 날 대륙 곳곳에서 시간이 멈췄습니다. 멈춘 틈에서는 잘못 쓰인 주문의 잔해인 **버그**들이 괴물이 되어 흘러나왔습니다. 버그는 무기로는 쓰러뜨릴 수 없고, 올바른 주문(정답 코드)을 시전해야만 정화됩니다.
- **시계 룬**: 지역마다 그 지역의 시간을 돌리는 시계 룬이 있습니다. 지역 보스가 시계 룬을 붙잡고 있으며, 보스를 쓰러뜨리면 시계 룬이 다시 돌기 시작하고 다음 지역으로 가는 길이 열립니다.
- **주인공**: 기억을 잃은 채 에코 마을 우물가에서 깨어난 '주문사'입니다. 서펜트 룬을 처음부터 다시 배워야 합니다. 이 설정은 플레이어가 Python 초급자라는 상황을 그대로 이야기에 반영한 것입니다.
- **할트(Halt)**: 최종 보스입니다. 원래는 세계의 모든 주문이 제시간에 끝나도록 관리하던 스케줄러였습니다. 그러나 '영원히 끝나지 않는 주문'이 세계를 집어삼킬까 두려워한 나머지, 아예 세계 전체를 멈춰 버렸습니다. 마지막 전투의 목표는 할트를 파괴하는 것이 아니라, 할트가 낸 시련을 모두 통과해 할트를 **정상 종료(exit code 0)** 시키는 것입니다.

### 2.2 스토리 흐름

| 막 | 지역 | 이야기 |
|---|---|---|
| 프롤로그 | 1 | 우물가에서 깨어난 주인공을 보조 캐릭터가 발견합니다. 마을을 덮친 첫 버그를 함께 정화하면서 동행이 시작됩니다. |
| 1막: 기초의 룬 | 1~4 | 마을과 숲, 동굴, 도서관을 지나며 주문의 기본 문법을 되찾습니다. 도서관에서 '대정지는 누군가 일부러 일으킨 것'이라는 기록을 발견합니다. |
| 2막: 도구와 효율 | 5~7 | 항구 도시에서 상인 길드의 도움을 받고, 사막에서 처음으로 '정답이지만 너무 느린 주문'이 시계 룬을 되살리지 못한다는 사실을 배웁니다. 할트의 이름이 처음 등장합니다. |
| 3막: 알고리즘의 길 | 8~11 | 광산, 신전, 평원, 미궁을 지나며 할트가 남긴 시련의 구조를 파악합니다. 보조 캐릭터의 과거가 드러납니다(§3의 '숨겨진 이야기'). |
| 4막: 깊은 땅 | 12~15 | 뿌리 숲, 황금 도시, 기억의 신전, 하늘 군도를 지나 정지의 탑으로 가는 길을 엽니다. |
| 종장 | 16 | 정지의 탑을 오르며 제한 시간이 있는 시련 세트(모의 코딩테스트)를 치릅니다. 마지막 층에서 할트를 정상 종료시키면 세계의 시간이 다시 흐릅니다. |

### 공통: 도트 초상화와 표정

- 초상화 크기는 48×48 픽셀로 하고, 대화창에서 3배로 확대해서 표시합니다.

- 대사 데이터에는 `"emotion": "worried"` 같은 필드만 적고, 엔진이 해당 표정 프레임을 고릅니다.

## 4. 핵심 게임 루프

### 4.1 지역 단위 루프

```
 탐험 ──▶ NPC·표지판·상자 ──▶ 레슨 (주문서 획득)
   ▲                              │
   │                              ▼
 다음 구역 해금 ◀── 보상 ◀── 전투 (코딩 문제)
   │
   └──▶ (지역 마지막) 보스전 ──▶ 시계 룬 회복 ──▶ 다음 지역 길 열림
```

- 레슨에서 얻은 **주문서**가 그 개념을 쓰는 몬스터와 싸우기 위한 열쇠입니다. 예를 들어 '분할의 주문서'(`input().split()`)를 얻기 전에는 해당 몬스터가 길을 막고 있어서 전투를 시작할 수 없습니다.
- 지역 안에서도 구역을 잠긴 문이나 무너진 다리로 나눠서, 새 개념을 배우는 순서를 맵 구조로 강제합니다.

### 4.2 하루 학습 루프 (15~30분 기준)

1. 접속하면 일일 퀘스트 3개와 스트릭을 확인합니다.
2. 마을의 '그림자 게시판'에서 오늘 복습할 그림자 몬스터(§7.6)를 처치합니다.
3. 진행 중인 지역에서 새 전투를 1~3개 치릅니다.
4. 캠프파이어에서 저장합니다. 진행도는 자동으로도 저장됩니다.

## 5. 메커니즘 상세

### 5.1 탐험

- **이동 방식**: 타일 한 칸 단위로 움직이는 그리드 이동을 씁니다. 자유 이동보다 구현과 충돌 판정이 단순하고, 고전 도트 RPG의 조작감과도 맞습니다.
- **상호작용 오브젝트**: NPC, 표지판, 상자, 잠긴 문, 숨겨진 방, 캠프파이어(저장 + HP 회복), 몬스터.
- **몬스터 조우는 심볼 인카운터로 합니다.** 심볼 인카운터는 맵 위에 몬스터가 보이고, 닿았을 때 전투가 시작되는 방식입니다. 걷다가 무작위로 전투가 시작되는 랜덤 인카운터는 쓰지 않습니다. 전투 하나가 문제 하나이고 몇 분씩 걸리기 때문에, 원하지 않는 순간에 전투가 시작되면 학습 흐름이 끊기기 때문입니다. 이미 처치한 몬스터는 맵에서 사라집니다.

### 5.2 레슨 (Boot.dev식 텍스트 레슨)

레슨 하나는 아래 순서로 진행되며, 5분 안에 끝나는 분량으로 만듭니다.

1. 보조 캐릭터가 대화로 개념을 소개합니다. 왜 필요한지부터 한 줄로 짚습니다.
2. 설명과 예제 코드를 보여 줍니다. **JavaScript와 비교하는 박스**를 넣습니다. 예를 들어 `"1" + 2`는 JS에서 `"12"`가 되지만 Python에서는 `TypeError`가 난다는 점을 보여 줍니다.
3. 예제 코드를 에디터에서 직접 실행해 봅니다.
4. 미니 연습(빈칸 채우기 또는 아주 짧은 문제)을 풉니다. 채점은 하지만 HP는 깎이지 않습니다.
5. 주문서를 얻고 코덱스에 등록됩니다. 코덱스에서는 언제든 레슨 본문과 예제를 다시 열람하고 실행할 수 있습니다.

### 5.3 전투 = 코딩 문제

#### 화면 구성

```
┌───────────────────────────────────────────────────────────────┐
│  [적 도트]  타입 슬라임  HP ■■■■■□□  (숨겨진 테스트 7개)        │
│  [나]       HP ■■■■■■■■■ 92/100                               │
├──────────────────────────┬────────────────────────────────────┤
│ 문제 본문 (Markdown)       │  코드 에디터 (CodeMirror)           │
│ 입력 / 출력 / 예제          │                                    │
│                          │                                    │
├──────────────────────────┴────────────────────────────────────┤
│ [초상화] 보조 캐릭터 대사 / 실행 결과 / Traceback 해설             │
│ [예제 실행]  [시전(제출)]  [힌트 1·2·3]  [코덱스]  [후퇴]          │
└───────────────────────────────────────────────────────────────┘
```

- **예제 실행**: 문제에 공개된 예제로만 실행합니다. 대가가 없으므로 마음껏 시험해 볼 수 있습니다. 직접 입력값을 넣어 실행하는 것도 가능합니다.
- **시전(제출)**: 숨겨진 테스트케이스 전체로 채점합니다. 테스트를 하나 통과할 때마다 적에게 타격 연출이 나갑니다.

#### 판정과 연출

| 판정 | 의미 | 연출 | 플레이어 피해 |
|---|---|---|---|
| AC | 모든 테스트 통과 | 적 정화, 보상 획득 | 없음 |
| WA | 출력이 틀림 | 주문이 빗나가고 적이 반격 | 적 공격력 × (1 − 통과율) |
| RE | 실행 중 에러 | 주문이 폭발하고 보조 캐릭터가 Traceback을 해설 | WA와 같음 |
| TLE | 시간 제한 초과 | 시간이 멈추는 연출, 보조 캐릭터가 느린 부분을 짚어 줌 | WA와 같음 |

- **적을 쓰러뜨리려면 한 번의 시전에서 모든 테스트를 통과해야 합니다.** 일부만 통과하면 적은 버티고, 다음 시전에서는 HP가 가득 찬 상태로 다시 시작합니다. 백준처럼 부분 점수가 없는 채점 방식을 그대로 체감하게 하려는 선택입니다. 대신 통과율이 높을수록 반격이 약해지므로, 거의 다 맞힌 시도와 전혀 못 맞힌 시도가 구분됩니다.
- **HP가 0이 되면** 전투에서 이탈해 마지막 캠프파이어로 돌아갑니다. 작성한 코드는 보존되고 골드나 아이템은 잃지 않습니다. 다만 '쓰러짐' 기록이 복습 시스템(§7.6)에 반영됩니다.
- **막혔을 때 빠져나오는 길**: 같은 적에게 세 번 쓰러지면 '해설서'를 열 수 있습니다. 해설서는 모범답안과 풀이를 보여 주고, 그 전투의 보상은 0이 되며 해당 개념이 그림자 몬스터로 확정 등록됩니다. 한 문제에 영원히 갇히는 상황을 막기 위한 장치입니다.

#### 힌트 3단계

| 단계 | 내용 | 대가 |
|---|---|---|
| 1. 방향 | 무엇을 의심해 봐야 하는지 | 이번 전투 보상 −10% |
| 2. 핵심 아이디어 | 써야 할 개념이나 공식 | 보상 −25%, 그림자 몬스터 등록 |
| 3. 부분 코드 | 풀이의 뼈대 코드 | 보상 −50%, 그림자 몬스터 등록 |

대가는 누적되지 않고, 사용한 가장 높은 단계의 대가만 적용합니다. 장신구 '길잡이 깃털'을 장착하면 1단계 힌트를 전투마다 한 번 무료로 볼 수 있습니다.

#### Traceback 해설

Python 에러 메시지는 초급자에게 낯설기 때문에, 보조 캐릭터가 쉬운 말로 풀어서 설명합니다. 오프라인에서 동작해야 하므로 AI 호출 없이 규칙 기반으로 만듭니다.

1. Traceback에서 **사용자 코드의 줄 번호**만 골라내고, 에디터에서 그 줄을 강조합니다. 채점기 내부 코드의 줄은 감춥니다.
2. 예외 종류(`NameError`, `TypeError`, `IndexError` 등)별 기본 해설을 보여 줍니다.
3. 메시지 패턴이 사전에 있으면 더 구체적인 해설로 바꿉니다. 예를 들어 `can only concatenate str (not "int") to str`를 만나면 "문자열과 숫자를 `+`로 이으려고 했어요. JS라면 자동으로 문자열로 바뀌지만 Python은 바꿔 주지 않아요."라고 설명합니다.
4. 해설 사전은 `content/companion/traceback.json`에 두므로, 엔진 코드를 고치지 않고 해설을 늘릴 수 있습니다.

#### 오답 진단

문제 데이터에 '자주 하는 실수' 패턴을 함께 적어 둘 수 있습니다. 예를 들어 출력이 `.0`으로 끝나면 "`/` 대신 `//`를 써 보세요"라고 안내합니다. 이 패턴은 §8의 오답 예시에서 그대로 가져옵니다.

#### 보스전

- 보스전은 2~3개 페이즈로 나뉩니다. **1페이즈는 정확성**, **2페이즈는 '시간 결계'**입니다.
- 시간 결계 페이즈에서는 큰 입력과 시간 제한이 걸립니다. 정답이라도 시간복잡도가 나쁘면 제한 시간 안에 끝나지 않아 실패합니다. 예를 들어 첫 보스는 반복문으로 합을 구하는 O(N) 풀이를 막고 공식을 쓰는 O(1) 풀이만 통과시킵니다.
- 화면에는 실행 시간을 '시간 게이지'로 보여 줍니다. 제한 시간 대비 몇 %를 썼는지 보이므로, 개선 전후의 차이를 눈으로 확인할 수 있습니다.
- 시간 제한의 보정 방식은 기술 리서치 결과에 맞춰 §9에서 정합니다.

### 5.4 퍼즐

전투만 반복되면 단조롭기 때문에, 코드를 '읽는' 능력을 쓰는 가벼운 퍼즐을 섞습니다. 코딩테스트에서도 자기 코드를 머릿속으로 실행해 보는 능력이 중요합니다.

| 퍼즐 | 방식 | 예 |
|---|---|---|
| 잠긴 문 | 코드를 보고 출력을 예측해서 입력 | `print(7 // 2, 7 % 2)`의 출력은? |
| 고장 난 다리 | 버그가 있는 코드를 고쳐서 테스트 통과 | `range(1, n)`을 `range(1, n + 1)`로 고쳐야 다리가 이어짐 |
| 표지판 수수께끼 | 표지판의 코드를 해석해서 숨겨진 방 위치 찾기 | "`len('serpent')`걸음 동쪽, `2 ** 2`걸음 북쪽" |
| 빈칸 주문 | 레슨의 미니 연습 | `a, b = map(___, input().split())` |

### 5.5 문제 형식과 채점 규칙

| 형식 | 실전 대응 | 플레이어가 쓰는 것 | 채점 방법 |
|---|---|---|---|
| 함수 구현형 | 프로그래머스 | `def solution(...)` | 테스트마다 함수를 호출하고 반환값을 비교 (리스트·딕셔너리는 내용 비교, 실수는 허용 오차 옵션) |
| stdin/stdout형 | 백준 | 전체 프로그램 | 테스트 입력을 stdin으로 주고 출력 문자열을 비교 (각 줄 끝 공백과 마지막 개행 차이는 무시) |

- stdin형 문제에서는 `input()`과 `sys.stdin.readline()`이 모두 동작해야 합니다. 레슨과 대사에서는 `sys.stdin.readline`을 쓰는 습관을 꾸준히 권장합니다.
- 테스트마다 Python 전역 상태를 새로 만들어서, 이전 테스트에서 만든 변수가 다음 테스트에 남지 않게 합니다.

## 8. 첫 지역 상세와 샘플 문제

### 8.1 지역 1: 에코 마을

| 항목 | 내용 |
|---|---|
| 개념 | 입출력(`input`, `sys.stdin.readline`, `print`의 `sep`·`end`), 변수, 자료형(`int`, `float`, `str`, `bool`), 산술 연산자(`+ - * / // % **`), 형변환 |
| 분위기 | 시간이 멈춘 작은 마을입니다. 우물물이 공중에 멈춰 있고, 주민들은 말하던 도중에 굳어 있습니다. |
| 일반 전투 | 8~10개(아래 샘플 4개 + Phase 2에서 추가할 4~6개) |
| 보스 | 계단 미믹(P0105) |

#### 맵 구성

플레이어는 아래 순서로 구역을 지나갑니다. 각 구역의 출구는 그 구역의 몬스터가 막고 있으므로, 레슨에서 주문서를 얻고 전투에서 이겨야 다음 구역으로 갈 수 있습니다.

| 순서 | 구역 | 레슨 | 전투 | 탐험 요소 |
|---|---|---|---|---|
| 1 | 우물가(시작 지점) | L1-1 | 없음 | 프롤로그 대화, 보조 캐릭터 합류 |
| 2 | 마을 광장 | L1-2 | P0101 | 표지판, 굳어 버린 주민 NPC |
| 3 | 상점 거리 | L1-3 | P0102, P0103 | 상점(골드 사용법 안내), 상자 |
| 4 | 메아리 골목 | L1-4 | P0104 | 표지판 수수께끼로 찾는 숨겨진 방 |
| 5 | 시계탑 계단 | 없음 | P0105(보스) | 클리어하면 시계 룬이 다시 돌고 동쪽 문이 열림 |

#### 레슨과 주문서

| 레슨 | 획득 주문서 | 다루는 내용 | JavaScript 비교 포인트 |
|---|---|---|---|
| L1-1 | 목소리의 주문서 | `print`, `input`, `sep`·`end` 옵션 | `console.log`와 `print`의 차이. `prompt()`와 달리 `input()`은 언제나 문자열을 돌려줍니다. |
| L1-2 | 변환의 주문서 | `int()`, `float()`, `str()`, `input().split()`, `map(int, ...)` | `Number("3")`, `parseInt`와 비교합니다. JS에서 `"1" + 2`는 `"12"`가 되지만 Python에서는 `TypeError`가 납니다. |
| L1-3 | 산술의 주문서 | `/`와 `//`의 차이, `%`, `**`, 큰 정수 | JS의 `Math.floor(a / b)` 습관과 비교합니다. JS의 Number는 2^53까지만 정수를 정확히 다루지만, Python의 `int`는 크기 제한이 없습니다. |
| L1-4 | 빠른 귀의 주문서 | `sys.stdin.readline`, 줄 끝 개행 문자, `.strip()`, 문자열 곱셈 | JS의 `"ab".repeat(3)`은 Python에서 `"ab" * 3`입니다. |

- `map(int, input().split())`은 지역 6에서 배울 내장함수 `map`을 쓰지만, 코딩테스트 입력에서 가장 자주 쓰는 관용구이므로 지역 1에서는 "통째로 외우는 주문"으로 먼저 소개합니다. 원리는 지역 6에서 다시 설명합니다.
- 함수 구현형 문제(P0103)는 `def solution(...)` 틀을 미리 채워서 줍니다. 함수는 지역 6에서 배우므로, 지역 1에서는 "`return` 뒤에 답을 적는 칸"이라고만 안내합니다. JS의 `function solution(hp, atk) { return ...; }`과 같은 모양이라고 비교해 줍니다.

### 8.2 샘플 문제 공통 규칙

- 테스트 번호는 1부터 셉니다. '공개' 테스트는 문제 본문의 예제로 보여 주고 [예제 실행]에도 쓰입니다. [시전(제출)]은 공개 테스트와 숨김 테스트를 모두 채점합니다.
- stdin/stdout형은 각 줄 끝의 공백과 마지막 개행 차이를 무시하고 비교합니다(§5.5).
- 함수 구현형은 반환값을 Python의 `==`로 비교합니다. 큰 정수가 많으므로 테스트 값은 반드시 Python 쪽에서 파싱하고 비교합니다(§11).
- 로컬 검증 기준 시간 제한은 CPython에서 테스트 하나당 2초입니다. 게임 안의 시간 제한은 §9의 보정 방식을 따릅니다.
- 오답 예시마다 붙은 '진단'은 §5.3의 오답 진단 데이터로 그대로 옮깁니다.

### 8.3 샘플 문제 5개

#### P0101 금화 두 자루

- 적: 타입 슬라임 · 형식: stdin/stdout · 필요 주문서: 변환의 주문서 · 위치: 마을 광장

**본문**

> 광장의 상인이 금화 두 자루를 맡긴 채 굳어 버렸습니다. 두 자루에 든 금화 수를 합쳐서 장부에 적어 주세요.
>
> **입력**: 첫째 줄에 두 정수 a, b가 공백 하나를 사이에 두고 주어집니다. (0 ≤ a, b ≤ 10^18)
>
> **출력**: a + b를 출력합니다.

**테스트케이스**

| # | 구분 | 입력 | 기대 출력 | 확인하려는 것 |
|---|---|---|---|---|
| 1 | 공개 | `1 2` | `3` | 기본 동작 |
| 2 | 숨김 | `0 0` | `0` | 최솟값 |
| 3 | 숨김 | `7 0` | `7` | 한쪽이 0 |
| 4 | 숨김 | `999999999999999999 1` | `1000000000000000000` | 자릿수 올림 |
| 5 | 숨김 | `1000000000000000000 1000000000000000000` | `2000000000000000000` | 최댓값 |

**모범답안**

```python
a, b = map(int, input().split())
print(a + b)
```

풀이 포인트: Python의 `int`는 크기 제한이 없으므로 10^18끼리 더해도 정확합니다. JS의 Number로는 `999999999999999999`를 정확히 담을 수조차 없습니다.

**오답 A. 형변환 누락**: 테스트 1~5 모두 WA

```python
a, b = input().split()
print(a + b)
```

- 진단(출력이 두 입력을 이어 붙인 모양일 때): "`input()`은 문자열을 돌려줘요. 그래서 `+`가 덧셈이 아니라 이어 붙이기가 됐어요. `int()`로 바꿔 보세요."

**오답 B. float 변환**: 테스트 1~5 모두 WA

```python
a, b = map(float, input().split())
print(a + b)
```

- 진단(출력이 `.0`으로 끝날 때): "`float`는 소수점이 붙어서 출력되고, 큰 수에서는 정밀도도 잃어요. 정수는 `int`로 바꿔 주세요."

**힌트**

1. 방향: `input()`이 돌려주는 값의 자료형을 확인해 보세요.
2. 핵심 아이디어: `split()`으로 나눈 뒤 각각 `int()`로 바꿉니다.
3. 부분 코드: `a, b = map(int, ____.split())`

#### P0102 공평한 분배

- 적: 나머지 박쥐 · 형식: stdin/stdout · 필요 주문서: 산술의 주문서 · 위치: 상점 거리

**본문**

> 마을 창고에 있던 금화 a개를 주민 b명에게 똑같이 나눠 주려고 합니다. 한 사람이 받는 금화 수와, 나눠 주고 남는 금화 수를 구하세요.
>
> **입력**: 첫째 줄에 두 정수 a, b가 공백 하나를 사이에 두고 주어집니다. (0 ≤ a ≤ 10^18, 1 ≤ b ≤ 10^18)
>
> **출력**: 한 사람이 받는 금화 수와 남는 금화 수를 공백 하나로 구분해 출력합니다.

**테스트케이스**

| # | 구분 | 입력 | 기대 출력 | 확인하려는 것 |
|---|---|---|---|---|
| 1 | 공개 | `7 2` | `3 1` | 기본 동작 |
| 2 | 숨김 | `0 5` | `0 0` | a = 0 |
| 3 | 숨김 | `5 7` | `0 5` | a < b |
| 4 | 숨김 | `10 10` | `1 0` | 나누어떨어짐 |
| 5 | 숨김 | `1000000000000000000 3` | `333333333333333333 1` | 큰 수(float 정밀도 함정) |
| 6 | 숨김 | `999999999999999999 2` | `499999999999999999 1` | 큰 수(float 정밀도 함정) |
| 7 | 숨김 | `1000000000000000000 1000000000000000000` | `1 0` | 최댓값 |

**모범답안**

```python
a, b = map(int, input().split())
print(a // b, a % b)
```

풀이 포인트: `//`는 몫, `%`는 나머지입니다. 둘 다 정수끼리 계산하므로 큰 수에서도 정확합니다.

**오답 A. / 사용**: 테스트 1~7 모두 WA

```python
a, b = map(int, input().split())
print(a / b, a % b)
```

- 진단(첫 번째 값에 소수점이 있을 때): "`/`는 나누어떨어져도 언제나 실수를 돌려줘요(`10 / 10`은 `1.0`). 몫만 필요하면 `//`를 쓰세요."

**오답 B. int(a / b)**: 테스트 5, 6만 WA

```python
a, b = map(int, input().split())
print(int(a / b), a % b)
```

- 진단(작은 수는 맞고 큰 수에서만 틀릴 때): "`a / b`가 실수(float)를 거치면서 16자리 이후가 뭉개졌어요. 예를 들어 `int(10**18 / 3)`은 `333333333333333312`가 돼요. `//`를 쓰면 정수끼리 계산해서 정확해요."

**힌트**

1. 방향: 나눗셈 결과에서 소수점 아래를 버리는 연산자가 따로 있어요.
2. 핵심 아이디어: 몫은 `//`, 나머지는 `%`로 구합니다.
3. 부분 코드: `print(a // b, a ____ b)`

#### P0103 몇 번 때려야 할까

- 적: 철갑 두더지 · 형식: 함수 구현형 · 필요 주문서: 산술의 주문서 · 위치: 상점 거리

**본문**

> 철갑 두더지의 체력은 hp이고, 한 번 때릴 때마다 체력이 atk씩 줄어듭니다. 체력이 0 이하가 되면 두더지가 쓰러집니다. 두더지를 쓰러뜨리려면 최소 몇 번 때려야 하는지 반환하도록 `solution` 함수를 완성하세요.
>
> **제한**: hp와 atk는 정수이고, 1 ≤ hp, atk ≤ 10^18입니다.

처음 주어지는 코드:

```python
def solution(hp, atk):
    answer = 0
    return answer
```

**테스트케이스**

| # | 구분 | hp | atk | 반환값 | 확인하려는 것 |
|---|---|---|---|---|---|
| 1 | 공개 | `10` | `3` | `4` | 나누어떨어지지 않음 |
| 2 | 공개 | `9` | `3` | `3` | 나누어떨어짐 |
| 3 | 숨김 | `1` | `1` | `1` | 최솟값 |
| 4 | 숨김 | `1` | `1000000000000000000` | `1` | atk가 hp보다 큼 |
| 5 | 숨김 | `1000000000000000000` | `1` | `1000000000000000000` | 최댓값 |
| 6 | 숨김 | `999999999999999999` | `1` | `999999999999999999` | float 정밀도 함정 |
| 7 | 숨김 | `1000000000000000000` | `3` | `333333333333333334` | 큰 수에서 올림 |

**모범답안**

```python
def solution(hp, atk):
    return (hp + atk - 1) // atk
```

풀이 포인트: hp ÷ atk를 올림한 값이 답입니다. 나누기 전에 `atk - 1`을 더하면, 나누어떨어지지 않을 때만 몫이 1 늘어납니다. `-(-hp // atk)`도 같은 결과를 냅니다. 둘 다 정수 연산만 쓰므로 큰 수에서도 정확합니다.

**오답 A. 내림 나눗셈**: 테스트 1, 4, 7 WA

```python
def solution(hp, atk):
    return hp // atk
```

- 진단(반환값이 정답보다 정확히 1 작을 때): "나누어떨어지지 않으면 마지막으로 한 번 더 때려야 해요. 내림이 아니라 올림이 필요해요."

**오답 B. math.ceil(float)**: 테스트 6, 7 WA

```python
import math
def solution(hp, atk):
    return math.ceil(hp / atk)
```

- 진단(작은 수는 맞고 큰 수에서만 틀릴 때): "`hp / atk`가 실수를 거치면서 정밀도를 잃었어요. `999999999999999999 / 1`조차 `1e+18`이 돼요. 정수 연산만으로 올림하는 방법을 찾아보세요."

**힌트**

1. 방향: 나누어떨어지지 않으면 한 번 더 때려야 해요.
2. 핵심 아이디어: 올림 나눗셈을 정수 연산만으로 만들어 보세요. `/`를 쓰면 큰 수에서 틀려요.
3. 부분 코드: `return (hp + ____) // atk`

#### P0104 메아리 주문

- 적: 메아리 유령 · 형식: stdin/stdout · 필요 주문서: 빠른 귀의 주문서 · 위치: 메아리 골목

**본문**

> 메아리 골목의 유령은 같은 주문을 n번 되풀이해서 들어야 사라집니다. 주문 s를 n번 이어 붙인 문자열을 출력하세요.
>
> **입력**: 첫째 줄에 주문 s가 주어집니다. s는 영어 소문자로만 이루어져 있고 길이는 1 이상 10 이하입니다. 둘째 줄에 정수 n이 주어집니다. (1 ≤ n ≤ 100)
>
> **출력**: s를 n번 이어 붙인 문자열을 한 줄에 출력합니다.

**테스트케이스**

| # | 구분 | 첫째 줄 s | 둘째 줄 n | 기대 출력 | 확인하려는 것 |
|---|---|---|---|---|---|
| 1 | 공개 | `ab` | `3` | `ababab` | 기본 동작 |
| 2 | 숨김 | `z` | `1` | `z` | 최솟값 |
| 3 | 숨김 | `python` | `2` | `pythonpython` | 일반 단어 |
| 4 | 숨김 | `abcdefghij` | `100` | `abcdefghij`를 100번 이어 붙인 1000자 문자열 | 최댓값 |

**모범답안**

```python
import sys
input = sys.stdin.readline
s = input().strip()
n = int(input())
print(s * n)
```

풀이 포인트: `sys.stdin.readline`은 줄 끝의 개행 문자(`\n`)까지 돌려줍니다. `int()`는 앞뒤 공백과 개행을 알아서 무시하지만, 문자열에는 개행이 그대로 남으므로 `.strip()`으로 지워야 합니다. `input = sys.stdin.readline`처럼 이름을 덮어쓰는 방식은 백준 Python 풀이에서 흔히 쓰는 관용구입니다.

**오답 A. strip 누락**: 테스트 1, 3, 4 WA

```python
import sys
input = sys.stdin.readline
s = input()
n = int(input())
print(s * n)
```

- 진단(출력 중간에 줄바꿈이 끼어 있을 때): "readline이 읽은 개행 문자까지 함께 반복됐어요. `s`를 `.strip()`으로 정리해 보세요."
- 참고: 테스트 2는 n = 1이라서 개행이 출력 끝에만 붙고, 마지막 개행 차이를 무시하는 비교 규칙 때문에 통과합니다. 그래서 n = 1인 테스트만으로는 이 실수를 잡을 수 없습니다.

**오답 B. str + int**: 테스트 1~4 모두 RE

```python
import sys
input = sys.stdin.readline
s = input().strip()
n = input()
print(s * n)
```

- 진단(`TypeError: can't multiply sequence by non-int of type 'str'`): "문자열에 문자열을 곱하려고 했어요. 반복 횟수 `n`을 `int()`로 바꿔 주세요." §3의 에러 해설 대사 예시가 바로 이 경우입니다(누리: "어, 폭발했다! ... `n`을 `int()`로 감싸 볼래?").

**힌트**

1. 방향: readline이 돌려준 문자열 끝에 무엇이 붙어 있는지 `print(repr(s))`로 확인해 보세요.
2. 핵심 아이디어: `.strip()`으로 개행을 지우고, 문자열에 정수를 곱하면 그 횟수만큼 반복됩니다.
3. 부분 코드: `print(s.strip() * ____)`

#### P0105 [보스] 계단 미믹

- 형식: stdin/stdout · 필요 주문서: 지역 1의 주문서 전부 · 위치: 시계탑 계단

**본문**

> 시계탑으로 오르는 계단 가운데 하나가 미믹이었습니다! a번 계단부터 b번 계단까지, 모든 계단 번호의 합을 외쳐야 미믹이 정체를 드러냅니다.
>
> **입력**: 첫째 줄에 두 정수 a, b가 공백 하나를 사이에 두고 주어집니다. (1 ≤ a ≤ b ≤ 10^18)
>
> **출력**: a + (a + 1) + … + b를 출력합니다.

**페이즈와 테스트케이스**

| # | 페이즈 | 구분 | 입력 | 기대 출력 | 확인하려는 것 |
|---|---|---|---|---|---|
| 1 | 1페이즈(정확성) | 공개 | `1 10` | `55` | 기본 동작 |
| 2 | 1페이즈(정확성) | 숨김 | `5 5` | `5` | a = b |
| 3 | 1페이즈(정확성) | 숨김 | `3 7` | `25` | a > 1 |
| 4 | 2페이즈(시간 결계) | 숨김 | `1 1000000000000000000` | `500000000000000000500000000000000000` | 최대 범위 |
| 5 | 2페이즈(시간 결계) | 숨김 | `100000000000000000 1000000000000000000` | `495000000000000000550000000000000000` | 큰 범위 |
| 6 | 2페이즈(시간 결계) | 숨김 | `1000000000000000000 1000000000000000000` | `1000000000000000000` | a = b인 최댓값 |

1페이즈를 통과하면 보스가 '시간 결계'를 펼치고 2페이즈가 시작됩니다. 2페이즈에서는 §5.3의 시간 게이지가 표시됩니다.

**모범답안**

```python
a, b = map(int, input().split())
print((a + b) * (b - a + 1) // 2)
```

풀이 포인트: 등차수열의 합 공식 '(첫 항 + 끝 항) × 항의 개수 ÷ 2'를 씁니다. 항의 개수 `b - a + 1`이 홀수이면 a와 b의 홀짝이 같아서 `a + b`가 짝수가 되므로, `(a + b) * (b - a + 1)`은 언제나 짝수입니다. 그래서 `// 2`로 나눠도 버려지는 값이 없습니다.

**오답 A. / 사용**: 테스트 1~6 모두 WA

```python
a, b = map(int, input().split())
print((a + b) * (b - a + 1) / 2)
```

- 진단(출력이 `.0`으로 끝나거나 `e+`가 들어 있을 때): "`/`는 실수를 돌려줘요. 공식은 맞았으니 `//`로 바꿔 보세요."

**오답 B. int(float)**: 테스트 4, 5 WA

```python
a, b = map(int, input().split())
print(int((a + b) * (b - a + 1) / 2))
```

- 진단(작은 수는 맞고 큰 수에서만 틀릴 때): "`/`에서 실수를 거치면서 정밀도를 잃었어요. P0102에서 본 함정과 같아요."

**비효율 답안. 반복문으로 하나씩 더하기**: 테스트 1~3, 6은 통과하고 테스트 4, 5는 TLE

```python
a, b = map(int, input().split())
total = 0
for x in range(a, b + 1):
    total += x
print(total)
```

- 진단(TLE): "주문은 맞았지만 너무 느려요. 10^18번 반복하면, 1초에 1억 번씩 더해도 300년이 넘게 걸려요. 반복하지 않고 한 번에 계산하는 방법이 있어요."

**설계 메모**: 반복문은 지역 2에서 배우지만, 플레이어는 JS 경험이 있으므로 반복문부터 떠올릴 가능성이 큽니다. 1페이즈를 반복문으로도 통과할 수 있게 해 두면, '정답이지만 느린 풀이'가 2페이즈에서 막히는 경험을 첫 보스에서 하게 됩니다. 이 경험은 지역 7(시간복잡도)의 복선이 됩니다.

**힌트**

1. 방향: 반복문이 10^18번 돈다면 얼마나 걸릴지 계산해 보세요.
2. 핵심 아이디어: 1부터 10까지의 합을 (1 + 10), (2 + 9), … 처럼 짝지어 보세요(가우스의 방법).
3. 부분 코드: `print((a + b) * (____) // 2)`
