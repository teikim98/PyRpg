## 1. 지역 개요

| 항목 | 내용 |
|---|---|
| ID / 폴더 | `r07` / `content/regions/r07-hourglass-desert/` |
| 이름 | 모래시계 사막 |
| 개념 | 입력 끝까지 읽기(`sys.stdin.read`, `for line in sys.stdin`, `EOFError`)와 `try/except` 정식 소개, 시간복잡도(입력 크기로 목표 복잡도 정하기, 숨은 O(N) 연산), 성능 습관(list와 set·dict의 찾기 비용), 정수론 기초(소수 판정 O(√N), 에라토스테네스의 체, GCD/LCM, 진법) |
| 분위기 | 강이 끝나는 곳에서 시작하는 붉은 사막. 거대한 모래시계들이 모래에 반쯤 묻혀 있고, 대정지 뒤로 모래가 떨어지다 만 채 공중에 멈춰 있습니다. 한낮의 주황과 모래색 위에 청록 오아시스와 밤하늘 남색이 강조색입니다 |
| 이야기 | 거울 호수에서 떠난 배는 강이 모래에 삼켜지는 마른 나루에서 멈춥니다. 대상(隊商) 길잡이가 "사막의 모래시계는 제시간에 끝나는 주문만 받아들인다"고 알려 줍니다. 여기서 처음으로 **정답이지만 너무 느린 주문은 시계 룬을 되살리지 못한다**는 사실이 이야기의 중심이 됩니다. 신기루 시장의 길목을 막은 **모래 전갈**(중간 보스)을 지나, 사막 한가운데 제단의 **모래시계 스핑크스**(최종 보스)를 정화하면 모래가 다시 흐릅니다. 스핑크스는 자신을 세운 존재를 **할트**라고 부르며, 할트의 이름이 이 지역에서 처음 나옵니다(2막의 끝). 스핑크스를 이기면 모래시계 부적을 얻습니다 |
| 보스 | 중간: 모래 전갈(P0707, 질문마다 `x in list` → `set`). 최종: 모래시계 스핑크스(P0714, 수마다 소수 판정 → 에라토스테네스의 체) |

- 모든 문제는 지역 1~6의 품질 기준(공개 1 + 숨김 3 이상, 경계값, 오답 2개 이상과 진단, 힌트 3단계, 변형 2개)을 따릅니다. 함수형은 `def solution` 틀을 `starter.py`로 줍니다.
- 진단에 넣을 흔한 실수: `sys.stdin.read()`의 끝 줄바꿈과 빈 문자열(`int('')`의 `ValueError`), `except:`로 모든 예외를 삼킴(→ "어떤 예외를 받을지 이름을 적자"), `EOFError` 대신 다른 예외를 받음, 반복 안에서 `set(arr)`을 매번 만듦(TLE), `x in list`(TLE), 소수 판정에서 `i * i < n`(완전제곱수를 소수로 봄)·`range(2, n)`(TLE)·1을 소수로 봄, `math.sqrt` 반올림 오차, `a * b // gcd`에서 `/`를 써서 실수가 됨, 진법 변환에서 0을 빈 문자열로 출력, 나머지를 뒤집지 않음, 10 이상 숫자를 글자로 바꾸지 않음.
- 보상: 일반·연습 100 XP / 50골드, 응용 통합형 200 / 100, 판별형 300 / 100, **중간 보스 400 / 200**, 최종 보스 1000 / 500(design.md §7.1~7.2). 공격력: 일반·연습 20, 응용 25, **중간 보스 30**, 최종 보스 40(지역 6과 같은 단계).
- `explanation.md`(해설서 설명)에는 실행 가능한 완성 답을 넣지 않습니다. 풀이 생각과 핵심 한두 줄만 둡니다(해설서 '설명 먼저'가 뜻이 있게, improvements-plan.md §10).

## 4. 응용 전투

두 문제 모두 `"applied": true`, `requires`는 지역 주문서 5개 전부, 마지막 레슨 비석(L7-5) 뒤·보스 앞에 둡니다(design.md §6.2). 제목·몬스터 이름에 도구·동작·주문서 이름을 쓰지 않고, 주문서에 묶이지 않은 스프라이트를 새로 그립니다(§7 아트). 지문은 조건 3~4개 + 예외 1개 이상 + 입력 범위. **힌트 1단계는 도구 이름 없이 방향만**, 2단계에서 개념을 밝힙니다.

### 4.1 P0712 낙타 대상의 짐(통합형, 필수, 200 XP / 100골드)

- 이야기: 대상의 짐 장부가 모래 폭풍에 망가졌습니다. 짐을 낙타들에게 똑같은 무게 묶음으로 나누려면 가장 큰 묶음 무게를 구해야 합니다.
- 입력: 줄 수가 주어지지 않습니다. 줄마다 `짐이름 무게`. 조건 ① 무게 자리가 정수가 아닌 줄은 깨진 줄이라 건너뜀 ② 같은 짐 이름이 다시 나오면 처음 것만 셈 ③ 무게가 0인 짐은 나눌 필요가 없어 뺌 ④ 남은 무게들의 최대공약수를 출력. **예외**: 남은 짐이 하나도 없으면 `0`. 범위: 줄 수 ≤ 10만, 무게 ≤ 10^12, 이름은 영어 소문자 1~10자.
- 섞는 개념: 입력 끝까지 읽기와 `try/except`(L7-1), 본 이름 set(L7-3), GCD(L7-5), 문자열 `split`(지역 4).
- 힌트 1(방향만): "줄마다 세 가지를 차례로 걸러 내고, 남은 무게를 하나씩 합쳐 가며 '모두를 나누는 가장 큰 수'를 갱신해 봐." 힌트 2: "깨진 줄은 `try/except ValueError`, 다시 나온 이름은 set, 나누는 수는 `math.gcd`를 누적." 힌트 3: 뼈대 코드.
- 오답 예: 중복 이름도 셈, 무게 0을 빼지 않음(답은 같지만 짐이 0뿐인 경우 `0`이 아님을 확인하는 테스트로 갈림), 빈 결과에서 오류, 깨진 줄에서 멈춤.

### 4.2 P0713 사막 별자리 암호(판별형, 선택, 300 XP / 100골드)

- 이야기: 별자리 석판의 수 n을 k진법으로 적으면 숫자 0이 별자리를 가르는 빈칸이 됩니다. 0으로 나뉜 조각을 **10진수로 읽은 값**이 소수인 조각의 수를 구합니다(프로그래머스 92335 유형의 오리지널. 이야기·조건·입출력은 새로 씀).
- `solution(n, k)`: 조건 ① n을 k진법으로 바꿈 ② `0`을 기준으로 나눔(연속된 0 사이의 빈 조각은 버림) ③ 조각을 10진수 정수로 읽음 ④ 소수인 조각 수 반환. **예외**: 1은 소수가 아님. 범위: 1 ≤ n ≤ 10^6, 3 ≤ k ≤ 10.
- **판별 포인트**: 조각 값이 10^12를 넘을 수 있어(예: 3진법 13자리를 10진수로 읽음) **체를 만들 수 없고**, 조각이 몇 개 안 되므로 조각마다 √N 판정이 맞는 도구입니다. 같은 지역에서 배운 체를 그대로 쓰려는 풀이는 메모리·시간 초과(숨김 테스트)로 막힙니다.
- 힌트 1(방향만): "조각이 얼마나 커질 수 있는지, 그리고 몇 개나 나오는지 먼저 어림해 봐." 힌트 2: "조각은 최대 10^12를 넘어서 표를 미리 만들 수 없어. 조각마다 √까지 나눠 보는 판정이 맞아." 힌트 3: 뼈대 코드.
- 오답 예: 큰 체를 만들어 `MemoryError`/TLE(진단: "조각이 아주 클 수 있어. 표를 미리 만드는 방법이 맞는지 다시 생각해 봐"), 빈 조각을 `int('')`로 읽어 `ValueError`, 1을 소수로 셈, 조각을 k진수로 읽음.
- 실전 추천에는 92335를 넣지 않습니다(같은 유형이 게임 안에 있음, §8).

### 5.1 중간 보스 P0707 모래 전갈

- 이야기: 신기루 시장의 길목을 막은 모래 전갈이 "명부에 있는 상인만 지나간다"며 지나가려는 사람마다 명부를 처음부터 뒤집니다.
- 문제: 첫 줄 N, 다음 N줄에 명부의 상인 이름, 다음 줄 Q, 다음 Q줄에 지나가려는 사람 이름. 사람마다 명부에 있으면 `1`, 없으면 `0`을 한 줄씩 출력.
- 1페이즈 정확성: N, Q ≤ 1,000, 같은 이름 여러 번, 대소문자가 다른 이름(다른 사람), 명부에 없는 이름만 있는 경우.
- 2페이즈 시간 결계: N = Q = 200,000(`gen`, 이름은 영어 소문자 4~8자, 기대 출력 약 0.4 MB). 입력이 크므로 `sys.stdin.read().split()` 또는 `sys.stdin.readline`이 필요합니다(L7-1, 지역 1 L1-4).
- `targetComplexity`: `"O(N + Q)"`.
- `slow.py`: 명부를 list로 두고 질문마다 `x in names`(O(N × Q)). 모범답안: 명부를 set으로 한 번 만들고 질문마다 `in`. 정답으로 인정하는 답안: `alt_dict.py`(dict 키로 찾기). budgetUnits는 Pyodide에서 재서 **모든 인정 답안이 3배 이상 여유**가 되게 정하고, 같은 크기·같은 생성기면 `phases[2].stopOnTle`.
- 오답 예: 질문마다 `set(names)`을 새로 만듦(TLE, 진단: "set을 반복 밖에서 한 번만 만들자"), `input()`을 40만 번 불러 느림(TLE 경계 확인 후 진단 여부 결정), 출력에 `True`/`False`.
- `hints[0]`(방향): "질문 하나마다 명부를 처음부터 끝까지 훑고 있지 않아? 명부를 한 번 정리해 두면 찾기가 빨라질 수 있어."
- 문제 데이터: `"boss": true, "midBoss": true`, `requires`는 `scroll.stream`, `scroll.complexity`, `scroll.lookup`. `concept`은 `scroll.lookup`. 공격력 30.
- 복잡도 예측 질문 선택지(§9.2): `O(N × Q)`, `O(N + Q)`, `O(N²)`.

### 5.2 최종 보스 P0714 모래시계 스핑크스

- 이야기: 스핑크스는 모래시계에 새겨진 수들 가운데 '나눠지지 않는 수'만 모래를 흘려보낸다며 수수께끼를 냅니다. 스핑크스는 자신을 이 사막에 세운 존재를 **할트**라고 부릅니다(보스 시작 대사에 이름, 풀이 방향은 없음).
- 문제: 첫 줄 Q, 다음 줄에 수 Q개(공백 구분). 그중 소수의 개수와 소수의 합을 두 줄로 출력(같은 수가 여러 번 나오면 나온 만큼 셈).
- 1페이즈 정확성: Q ≤ 100, 수 ≤ 10,000. 0·1·2, 완전제곱수(49, 9409), 모두 합성수인 경우.
- 2페이즈 시간 결계: Q = 200,000, 수 ≤ 1,000,000(`gen`). 수의 대부분을 10^6 근처의 소수와 두 소수의 곱(두 소수 모두 500 이상)으로 채워 하나씩 판정이 √M까지 끝까지 돌게 하고, 서로 다른 값이 충분히 많게 해서 판정 결과를 dict에 기억하는 풀이도 막습니다(측정 후 확정).
- `targetComplexity`: `"O(M log log M + Q)"`(M은 수의 최댓값).
- `slow.py`: 수마다 `i * i <= n`까지 나눠 보는 판정(O(Q√M)). 모범답안: 입력의 최댓값까지 체를 한 번 만들고 표로 판정. 정답으로 인정하는 답안: `alt_slice.py`(슬라이스 대입으로 지우는 체 `is_prime[i*i::i] = [False] * len(range(i*i, m + 1, i))`, 레슨에서 다루지 않지만 실전에서 쓰는 풀이). budgetUnits는 Pyodide에서 재서 모든 인정 답안이 3배 이상 여유가 되게 정합니다. **판정을 dict에 기억하는 하나씩 판정**이 2페이즈에서 TLE인지 측정해 보고합니다(통과하면 생성기를 고치거나 인정 여부를 사용자에게 물음).
- 오답 예: 1을 소수로 셈, 체 크기를 고정 10^6 + 1이 아니라 입력 최댓값보다 작게 잡음(`IndexError`), `i * i < n`, 합 대신 개수만 출력.
- `hints[0]`(방향): "수마다 처음부터 나눠 보고 있다면, 같은 일을 20만 번 되풀이하는 셈이야. 한 번에 여러 수의 답을 미리 정해 둘 수는 없을까?"
- 문제 데이터: `"boss": true`, `requires`는 지역 주문서 5개 전부, `concept`은 `scroll.sieve`. 공격력 40.
- 보상 장신구: `content/items.json`의 `hourglass-charm`에 `"rewardFrom": "P0714"`를 더합니다(지역 2 보스의 `guide-feather`와 같은 방식). 효과는 단위 3-E5에서 만든 "시간 결계 TLE가 한 번 확정된 뒤 목표 복잡도 공개" 그대로입니다.
- 복잡도 예측 질문 선택지(§9.2): `O(Q × M)`, `O(Q√M)`, `O(M log log M + Q)`.

## 9. 함께 하는 시스템 작업

### 9.1 고장 난 다리 퍼즐(design.md §5.4)

지역 7에서 처음 만드는 퍼즐 형식입니다. 지금 `src/`에 퍼즐 처리 코드가 없습니다(improvements-plan.md §10).

- **데이터**: `content/regions/r07-hourglass-desert/puzzles/Z0701/`에 `puzzle.json`, `statement.md`, `starter.py`(버그가 든 시작 코드), `solution.py`(고친 코드). `puzzle.json`은 문제 형식(design.md §11.1)의 부분집합: `id`, `title`, `kind`, `entry`(함수형일 때), `source`(버그를 가져온 문제 ID와 오답 파일, 예: `{"problem": "P0708", "wrong": "wrong_a.py"}`), `tests`(공개 1 + 숨김 3 이상), `hints`(3단계), `dialogue`(풀었을 때 대사 ID).
- **Z0701 부서진 수로 다리**: 다리 장치의 '돌 판정 코드'가 49 같은 완전제곱수를 소수로 봅니다. 시작 코드는 P0708의 오답 `wrong_a.py`(`while i * i < n`)와 같은 버그이고, 한 글자(`<` → `<=`)를 고치면 테스트를 통과합니다. 학습 시점은 L7-4입니다.
- **맵**: `door` 오브젝트에 `puzzle=Z0701`(design.md §11.4). 문에 다가가 상호작용하면 퍼즐 창이 열립니다.
- **엔진**: 전투 화면을 '퍼즐 모드'로 재사용합니다. 적 스프라이트 대신 다리 그림, 적의 반격·HP 손실·보상·그림자 등록·해설서·연습 제안 없음, 힌트는 대가 없이 열림, 시작 코드는 `starter.py`(빈 틀이 아님). 통과하면 `flags["puzzle.solved:Z0701"]`을 저장하고 문을 열고(`removedObjects`), 다리 타일을 `canal_bridge`로 바꿔 보여 줍니다. 전투 수·일일 퀘스트·칭호에는 넣지 않습니다(design.md §5.4).
- **검증기**(`tools/verify_content.py`): 퍼즐마다 `solution.py`는 모든 테스트 AC, **`starter.py`는 하나 이상의 테스트에서 실패**, `starter.py`가 `source`의 오답 파일과 같은 버그를 담는지(내용이 같거나 diff가 작은지) 확인, 선행 지식 검사는 `solution.py`를 문제처럼 검사. 맵의 `puzzle` 참조가 실제 퍼즐을 가리키는지.
- **E2E**: 다리 앞에서 막힘 → 퍼즐 창 → 시작 코드 시전 실패 → 고쳐서 통과 → 다리가 이어지고 지나감 → 새로고침해도 이어진 상태.

### 9.2 보스 복잡도 예측 질문(design.md §5.3, 결정 23 P-D2)

- **데이터**: 보스 `problem.json`에 `"complexityChoices": [문자열 3개]`. `targetComplexity`가 그 가운데 하나여야 합니다(검증기). 지역 7부터 보스에 필수.

- **답을 알려 주는 시점**은 §11 질문 2의 결정을 따릅니다.
- **저장**: 고른 답을 `flags["complexity.guess:<문제 ID>"]`에 남깁니다(그림자전·연습 전투에서는 묻지 않음).
