## 5. 단위 3-1 세부 계약

### 5.1 그림자 몬스터용 변형 문제(design.md §7.6)

- `problem.json`에 선택 필드 `variants`를 둡니다. 변형은 같은 개념·같은 형식(입력·출력 규칙과 함수 시그니처가 원래 문제와 같음)이고, 이야기와 입력값만 바꿉니다. 그래서 원래 문제의 모범답안이 변형의 모든 테스트를 통과해야 합니다.

```json
"variants": [
  { "id": "P0101-v1", "title": "…", "statement": "variants/v1.md",
    "tests": [ { "in": "…\n", "out": "…\n", "public": true }, … ] },
  { "id": "P0101-v2", … }
]
```

- 문제마다 변형 2개, 변형마다 공개 1 + 숨김 3 이상. 보스 변형은 1페이즈만 만듭니다. 칸 3 이상 그림자에서는 엔진이 원래 보스의 2페이즈를 붙이므로(design.md §7.6, 구현 예정: E2), 보스 변형의 입출력 형식은 반드시 원래 보스와 같게 둡니다. 지역 7부터 변형 지문의 첫 문장에 원래 몬스터 이름을 쓰지 않습니다.
- 검증: `tools/verify_content.py`가 각 변형에 대해 모범답안 AC, `wrong[]` 오답은 하나 이상의 테스트에서 실패하는지 확인합니다.
- 로더는 변형을 `Problem.variants?: ProblemVariant[]`로 넘기고, 앱은 그림자 전투에서 변형을 돌려가며(마지막으로 낸 것과 다르게) 냅니다.

## 7. 지역 명세 형식(지역 7부터)

지역 6 명세(`region06-spec.md`)의 형식에 아래를 더하고 바꿉니다.

- **§2 레슨 표**: '다루는 내용' 열이 그 레슨 `lesson.json`의 `introduces`의 원본입니다. 새 내장 함수·메서드·모듈·문법을 빠짐없이 적습니다(예: `math.gcd`, `from math import`, `int(s, base)`, `try/except`).
- **§3 문제 표**: 열에 학습 시점(가장 뒤 레슨), 연습(○), 응용(통합/판별), 예상(분)을 두고, 표 아래에 "필수 일반 n개, 합계 m분"을 적습니다. "지역 1~N 개념만"이라고 쓰지 않고 "학습 시점까지 소개된 것만(선행 지식 검사)"이라고 씁니다.
- **응용 전투 절**: 두 문제의 유형, 섞는 개념, 조건과 예외, 보상, 스프라이트, 힌트 1단계가 도구 이름을 쓰지 않는지.
- **보스 절**: `targetComplexity`, 2페이즈 시작 대사와 보스 시작 대사(입력 크기만), `hints[0]`의 방향, `slow.py`의 학습 시점, 중간 보스 공격력.
- **퍼즐 절**: 고장 난 다리의 위치, 원본 문제와 `wrong_*.py`, 고칠 줄.
- **맵 절**: props 표시(연습 몬스터, 응용 전투, 중간 보스 뒤 캠프파이어, 퍼즐), 비석 순서.
- **실전 추천 표**: 문제 | 사이트 | 레벨 | 필요 개념 | 개념의 지역 | 도전.
- **검증 절**: 선행 지식 오류 0 · 경고 0(예외는 명세에 적은 것만), 연습 배치 검사, `applied` 형식·보상, `explanation.md`에 실행 가능한 완성 답이 없는지.
