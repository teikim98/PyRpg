## 1. 단위 3-0: Phase 2 설계 질문 반영

사용자가 "다음 플랜대로 진행"을 지시해서 아래 추천안을 적용합니다. 다른 결정을 주시면 해당 항목만 되돌립니다.

| # | 질문 | 적용 |
|---|---|---|
| 1 | 함수 구현형에서 `1` 대신 `True`를 반환하면? | 지금처럼 통과(Python `==` 기준). 실제 사이트도 같은지는 미확인 |
| 2 | P0108에서 리스트 대신 튜플 `h, m, s` 반환은? | 통과시킴. 문제 데이터에 `"sequenceAsList": true` 같은 비교 옵션을 두고, 기본 비교는 그대로 |
| 3 | 함수 구현형 채점 때 `if __name__ == "__main__":` 블록은? | 실행하지 않음(`__name__`을 모듈 이름으로) |
| 4 | 함수 구현형 [예제 실행]에서 `print` 출력은? | 결과 영역에 보여 줌(채점에는 영향 없음) |
| 5 | AC 직후 승리 배너를 누르기 전에 새로고침하면 승리가 사라짐 | AC 순간에 승리를 저장 |
| 6 | 시작 직후 로딩이 끝나기 전 이동 | 시작이 끝날 때까지 입력 막음 |
| 7 | 한글 입력 상태에서 Z로 대사가 안 넘어감 | 대화창도 `e.code`(KeyZ) 기준으로 |
| 8 | 오프라인 캐시에 옛 버전 파일이 쌓임 | 빌드마다 캐시 이름을 바꾸고 옛 캐시 삭제 |
| 9 | 공통 대사 `fatal_recursion`, `practice_suggest` 미사용 | 전투 UI가 공통 대사를 쓰도록 연결 |

## 5. 단위 3-1 세부 계약

### 5.1 그림자 몬스터용 변형 문제(design.md §7.6)

- `problem.json`에 선택 필드 `variants`를 둡니다. 변형은 같은 개념·같은 형식(입력·출력 규칙과 함수 시그니처가 원래 문제와 같음)이고, 이야기와 입력값만 바꿉니다. 그래서 원래 문제의 모범답안이 변형의 모든 테스트를 통과해야 합니다.

```json
"variants": [
  { "id": "P0101-v1", "title": "…", "statement": "variants/v1.md",
    "tests": [ { "in": "…\n", "out": "…\n", "public": true }, … ] },
  { "id": "P0101-v2", … }
]
```

- 문제마다 변형 2개, 변형마다 공개 1 + 숨김 3 이상. 보스는 1페이즈 테스트만 씁니다(그림자전은 시간 결계 없음).
- 검증: `tools/verify_content.py`가 각 변형에 대해 모범답안 AC, `wrong[]` 오답은 하나 이상의 테스트에서 실패하는지 확인합니다.
- 로더는 변형을 `Problem.variants?: ProblemVariant[]`로 넘기고, 앱은 그림자 전투에서 변형을 돌려가며(마지막으로 낸 것과 다르게) 냅니다.

### 5.2 마을 시설 오브젝트

- 에코 마을 광장에 `board_shadow`(종류 `board`: 그림자 게시판 + 일일 퀘스트), 상점 거리에 `shop_echo`(종류 `shop`)를 둡니다. 갈림길 숲 개울 쉼터에도 `board_shadow_r02`를 둡니다.
- 데이터: `content/items.json`(장신구·소모품·꾸미기, 가격), `content/titles.json`(칭호와 조건), `content/quests.json`(일일 퀘스트 풀).
