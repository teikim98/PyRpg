## 1. 공통 규칙

- 브랜치·커밋: CLAUDE.md "Git"대로 합니다. 커밋 메시지는 `Phase 3 단위 3-A(콘텐츠): …`, `Phase 3 단위 3-E1(엔진): …`처럼 단위 이름으로 시작합니다. 작성자는 `git -c user.name=Claude -c user.email=noreply@anthropic.com commit`. `main` 머지는 사용자가 요청할 때 합니다.
- worktree: CRLF 다시 체크아웃(`git rm -r --cached -q . && git reset -q --hard HEAD`), node_modules는 `mklink /J`로 연결하고 지울 때 먼저 `rmdir`, Playwright는 에이전트마다 `PW_PORT`를 다르게.
- 모든 단위가 고치지 않을 것: `art-overhaul`이 고치는 곳(`src/game/*`, `src/contracts/world.ts`·`assets.ts`, `src/ui/assets.ts`, `tools/art/*`, 모든 `map.tmj`, `tools/maps/build_r01~06.py`, `styles.css`의 스프라이트 애니메이션 `:371`·`:1756` 부근, `verify_content.py`의 독스트링 13행·상수 37~43행·`check_region`의 1207행 부근), `SAVE_VERSION`. E2E가 다시 찍은 `docs/` 스크린샷은 의도한 것만 경로를 지정해 커밋합니다.
- 검증은 단위마다 typecheck · `npx vitest run` · `npm run verify`를 돌리고, `src/`나 레슨·문제를 고친 단위는 전체 E2E(약 20분, 백그라운드)까지 돌립니다. P0411 시간 보정 테스트는 다른 E2E와 겹치면 흔들리므로 실패하면 단독으로 다시 확인합니다(결정 15).
- 단위가 끝나면 `progress.md`에 숫자로 기록하고, design.md §14(3-D가 만듦)의 상태 열과 해당 개선안 문서 재정리 절의 항목 상태를 "해결됨(단위 3-X)"으로 바꿉니다.
