## 1. 지금 상태와 문제

- 캐릭터 시트는 16×16 프레임 8개(4방향 × 2프레임). 걷기 애니메이션은 8fps(프레임당 125 ms)인데 한 칸 이동은 135 ms라, 한 걸음 동안 사실상 프레임 하나만 보이고 걸음이 끝나면 멈춘 프레임으로 돌아간다. 그래서 '미끄러지는' 것처럼 보인다(`src/game/WorldScene.ts` `createAnims`, `startMove`).
- 몬스터·보스는 2프레임 제자리 애니메이션(2fps). 타일은 전부 정지. 화면 연출 없음.
- 아트는 전부 `tools/art/*.py`가 코드로 그리고(결정적 빌드), `tools/art/check.py`가 계약(크기·프레임 수·불투명·바이트 동일 재빌드)을 검사한다. 이 방식은 그대로 쓴다.

## 3. 기술 계약 변경(엔진 담당이 먼저 넣고, 옛 형식도 계속 읽음)

| 대상 | 지금 | 바뀐 뒤 |
|---|---|---|
| 캐릭터(player, nuri, npc_*) | 16×16, 가로 8프레임 | **16×24 프레임, 가로 6열 × 세로 4행**(행 = 아래·왼쪽·오른쪽·위, 열 = 0 서기, 1 왼발, 2 서기, 3 오른발, 4 숨쉬기, 5 눈 깜빡임). manifest의 frameWidth 16·frameHeight 24로 구별하고, 16×16 8프레임 옛 시트도 그대로 동작 |
| 걷기 | 2프레임, 걸음마다 끊김 | 4프레임 걷기를 **걸음 사이에 끊지 않고 이어서**(한 걸음에 2프레임, 두 걸음에 한 주기), 발 딛는 프레임에서 몸이 1px 오르내림. 멈추면 서기 프레임, 잠시 뒤 숨쉬기·가끔 눈 깜빡임 |
| 누리 따라오기 | 플레이어와 같은 방식 | 같은 4프레임, 위상을 반 박자 어긋나게(둘이 똑같이 걷지 않게) |
| 몬스터·오브젝트 | 16×16 2프레임 | **16×16 4프레임** 제자리(통통 튀기·찌그러짐 등). 2프레임 옛 시트도 동작. obj_chest·obj_door는 [닫힘, 열림] 그대로 |
| 보스 | 32×32 2프레임 | **32×32 4프레임** |
| 초상화 | 64×64 | 64×64 그대로(그림만 새 화풍) |
| 타일 애니메이션 | 없음 | manifest `tileAnimations`: `{ "water": { "frames": ["water", "water_a1", "water_a2"], "fps": 3 } }`. 애니메이션 프레임 타일은 타일셋 **끝에 추가**(기존 순서·이름 불변, 맵 데이터 그대로) |
| 화면 연출 | 없음 | 카메라 필터(색 보정 ColorMatrix + 비네트), 지역별 분위기: `region.json`의 선택 필드 `ambience`(`grade`: 색 보정 프리셋 이름, `particles`: `sparkle`·`dust`·`leaves`·`spray`·`mist` 등). 전투·대화 화면(DOM)은 그대로 위에 뜸 |
| 경계 장식(결정 20) | 없음(타일 한 칸은 이웃을 몰라 풀 덤불·물가 경계를 못 그림) | manifest `edgeDecor`(조각 시트 `tiles/edges.png` + 타일 분류 `terrain` + 규칙 `rules`). 엔진이 ground 레이어 이웃 칸의 분류를 보고 조각(풀 덤불·물가·갑판 그늘·벽 발치 그늘)을 바닥 위·물체 아래 레이어에 얹음. 맵 데이터·충돌 불변, 지역 1~6 공통. 자세한 규칙은 style-guide.md §4.2 |
| 깊이(겹침) | 16×16 | 16×24 캐릭터의 머리가 위 칸 오브젝트·벽과 겹칠 때 y 기준 정렬이 맞는지(머리가 지붕 위로 올라오지 않게) |

- `src/contracts/assets.ts` 주석, `tools/art/check.py`, 단위 테스트를 새 계약에 맞춥니다.
- 성능: 필터·입자를 넣은 뒤 이 PC(Chromium)에서 프레임이 떨어지지 않는지 확인합니다.

## 7. LWITW 화풍(2026-10-21 시작, 보류 중)

사용자 요청으로 캐릭터부터 Little Witch in the Woods(LWITW, Sunny Side Up) 방식으로 다시 그리기 시작했습니다(결정 37·38). 주인공·누리 파일럿까지 하고 **지역 8을 먼저 하기로 해서 보류**했습니다(2026-10-21, 사용자 요청). 브랜치 `art-lwitw`(`00bfcef`). 규칙은 [`style-guide.md`](style-guide.md) §5에 있습니다.

### 7.1 분석에서 확인한 것(다시 조사하지 않아도 되게)

레퍼런스는 Steam 공식 스크린샷 22장(`https://store.steampowered.com/api/appdetails?appids=1594940`)과 Release Trailer입니다. 상용 이미지라 저장소에 넣지 않았고, 분석 원본(`rules.md`, 원본 픽셀 크롭)은 세션 임시 폴더에 있어서 사라졌습니다. 필요하면 같은 API에서 다시 받아 4px 격자로 샘플링합니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 화면 | 480×270을 정수 4배로 1920×1080에. 스프라이트 위치는 서브픽셀까지 허용(레이어끼리 1/4~3/4 게임 픽셀 어긋남) | 실측 22장 |
| 타일 | 16px(32px 묶음 무늬도 있음) | 실측 |
| 캐릭터 | 엘리 약 24×32(모자 포함), 사람 NPC 약 18×33~38. 타일보다 가로 1.5배, 세로 2배 | 실측 |
| 얼굴 | 머리카락이 감싼 창 약 8×6. 눈 1×1 두 개(사이 4px, 가장 어두운 색), 볼터치 2×1, 입 2×1, 코 없음, 얼굴 안 외곽선 없음 | 실측(원본 픽셀로 눈 1×1 재확인) |
| 머리카락 | 기본색을 넓게, 그늘은 가닥 사이 1px와 바깥쪽, 밝음 거의 없음. 옆머리가 허리까지 | 실측 |
| 외곽선·음영 | 재질마다 색 외곽선(순검정 아님), 2~3단 평평한 음영, 디더링 없음. 우리 코지 규칙과 같음 | 실측 |

| 배경 | 밝은 파스텔 바닥(풀 `7bc588`, 모래 `f3e197`), 환경 외곽선은 부드럽고 캐릭터가 화면에서 가장 어두운 값. 발밑 그림자 타원 약 12×2~3(바닥 × 약 0.65) | 실측·관찰. 배경은 아직 자세히 분석하지 않음 |
| 그 밖 | Unity + Aseprite, 대화 초상화도 도트(약 120×130, 4배), 노트 일러스트는 2배로 더 잘게, 빛 번짐·반투명 안개 | 실측·개발사 X |
