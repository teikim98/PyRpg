## 통합된 그림자·변형 출제 규칙

①(회전 출제, 이름 숨김, 보스 2페이즈, 대표 문제 갱신, 게시판 시점 결정), ③(미해결 문제의 대기, 연습 전투의 변형 사용), ④(시간 예산, 첫 1마리 예외, 보스 보정)를 합친 규칙입니다. 등록 규칙(개념 단위, 칸과 간격, 이동 규칙)은 design.md §7.6 그대로입니다.

**A. 등록과 대표 문제**
1. 같은 개념이 다시 등록되면 강등과 함께 대표 문제(`ShadowEntry.problemId`)를 이번에 막힌 문제로 바꿉니다(①).
2. (① 결정 6을 채택할 때만) 지역 8부터 지역 클리어 때 등록되지 않은 주문서 1개를 칸 3으로 등록합니다.

**B. 오늘의 목록과 문제를 정하는 순서**(그날 게시판을 처음 그릴 때 한 번 정하고, 같은 학습일에는 바꾸지 않습니다. 오늘 이전의 기록만으로 계산하면 따로 저장하지 않아도 같은 결과가 나옵니다(추론, 구현 때 확인). 오늘 치른 그림자는 목록에서 빠지기만 합니다.)
1. **후보**: 출현일이 오늘 이전인 그림자.
2. **대기**: 대표 문제를 아직 처치하지 못한 그림자는 게시판에 '대기'로만 보이고 후보에서 빠집니다. 원래 문제를 처치한 다음 학습일부터 후보가 됩니다(③).
3. **정렬**: 연체일이 긴 것 → 칸이 낮은 것(지금과 같음).
4. **낼 문제 고르기**(그림자마다)
   - 칸 0~2: 대표 문제의 변형을 돌려 냅니다. 직전에 낸 변형은 피합니다(지금과 같음).
   - 칸 3 이상: 같은 `concept`이고 이미 푼 문제(보스, 응용 전투, 연습 몬스터 포함) 가운데 직전에 그림자로 낸 원래 문제를 피해 하나를 고르고, 그 문제의 변형을 냅니다(①). 후보가 대표 문제 하나뿐이면 대표 문제를 냅니다. 고르는 순서는 "가장 오래 그림자로 나오지 않은 문제"로 정해 두면 결과가 늘 같습니다(추론).
   - 칸 3 이상에서 고른 문제가 보스이면 변형의 1페이즈 테스트 뒤에 원래 보스의 2페이즈 테스트, `phases`, `budgetUnits`를 붙이고, 2페이즈 시작 대사는 공통 문장을 씁니다(①).
5. **예상 시간**: 고른 원래 문제의 `estimatedMinutes`입니다. 보스는 1페이즈만 내면 절반(올림), 2페이즈를 붙이면 전체입니다(통합 결정 8).
6. **담기**: 정렬 순서대로 담되, 하루 최대 3마리이고, 오늘 이미 치른 그림자의 예상 시간과 담을 그림자의 예상 시간 합계가 15분을 넘는 지점에서 멈춥니다. 작은 것을 골라 건너뛰지 않습니다. 오늘 아직 그림자를 하나도 치르지 않았다면 첫 1마리는 시간과 관계없이 냅니다(④). 오늘 치른 분량은 기록의 변형 ID에서 원래 문제를 찾아 셉니다(통합 결정 7).
7. 게시판에는 "오늘 복습 예상 약 N분"을 함께 보여 줍니다(④).

**C. 화면과 결과**
1. 칸 3 이상의 그림자는 게시판, 적 이름, 제목에서 주문서 이름과 원래 몬스터 이름을 감추고 '이름 없는 그림자'로 나옵니다. 이긴 뒤에 어떤 주문서였는지 보여 줍니다(①, 이름 규칙은 통합 결정 22).
2. 보상은 실제로 낸 원래 문제 보상의 50%입니다. 보스는 페이즈와 관계없이 일반 전투 보상(100 XP·50골드)을 기준으로 합니다(통합 결정 8). 응용 전투가 걸리면 그 보상(200 또는 300 XP)의 50%입니다.
3. 그림자전에는 해설서, 연습 제안, 실전 시계가 없습니다(③, 통합 결정 4).

**D. 같은 출제 함수를 쓰는 다른 곳**
1. **연습 전투(③)**: 막힌 문제가 응용 전투가 아니면 ③의 순서(같은 개념의 이미 푼 문제의 변형 → 같은 주문서의 미해결 연습 몬스터 안내 → 몸풀기)로 찾고, 응용 전투이면 몸풀기만 제안합니다(통합 결정 9). 변형은 그날 게시판에 오른 문제를 피해서 고릅니다(통합 결정 10). 반격, 보상, 그림자 기록, 문제 기록이 없고, 하루 그림자 상한에 들어가지 않습니다.
2. **탑의 예행 연습(③, 지역 13~16)**: 그 지역까지 푼 일반 전투 2개의 변형을 칸 3 이상과 같은 이름 숨김 규칙으로 냅니다. 하루 그림자 상한에 들어가지 않습니다.

**E. 구현 단위**: 위 규칙은 `src/systems/shadows.ts`(`registerShadow`, `dueShadows`에 예상 분 함수와 대기 판정), `src/systems/shadowBoard.ts`(`shadowProblem`이 칸과 후보 목록을 받음, `plain`의 보스 처리, 보상 보정), `src/app/app.ts`(`fightShadow`, `boardView`, `questContext`), `src/contracts/ui.ts`(`BoardView`), `src/ui/board.ts`를 한 단위에서 함께 고칩니다. 지역 4 병합 직후 엔진 단계의 두 번째 단위로 둡니다(아래 로드맵).
